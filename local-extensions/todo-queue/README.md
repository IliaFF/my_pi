# Pi TODO Queue

Локальное расширение pi: постоянная очередь поверх проектного `TODO.md`.

## Этапы 1–2

- `+ <задача>` сохраняет задачу в `Pending`, не отправляя её модели.
- `/queue add|next|status` — ручная очередь.
- `/queue` и `/queue list` показывают все незавершённые задачи: `In progress`, `Pending`, `Blocked`. Завершённые скрыты из уведомления, но остаются в `TODO.md` и полном ответе `task_queue action=list`.
- `/queue edit|delete|move` — редактирование управляемых задач.
- `/queue run|pause|resume|skip` — безопасный автоматический разбор.
- Инструмент `task_queue` позволяет агенту добавлять, брать, завершать, блокировать и освобождать задачи. `claim` с `id` выбирает ровно этот пункт из Pending, без переупорядочивания; без `id` сохраняет FIFO. Неизвестный, пустой или не-pending ID отклоняется без записи. Ошибка возвращается через native tool error, а не успешный текст `Error:`. Цепочка release/move/claim для выбора конкретной задачи не нужна.
- Следующая задача запускается только после `task_queue.complete` и события `agent_settled`.
- Обычный `agent_end` ставит автоматический режим на паузу.
- За запуск выполняется не более пяти задач.

## Компактная панель

В доверенной TUI-сессии над редактором видны счётчики `Pending`/`Blocked` и дерево незавершённых задач: сначала текущая `◐` (выделенная строка), затем `○ Pending` в FIFO-порядке, затем `! Blocked`. Цвет дополняет символ, но не заменяет его. Остаток обозначен точным `+ N ещё`; полный текст доступен через `/queue`. Завершённые и отложенные идеи не показываются; пустая очередь скрывает панель. `/queue panel` или `Ctrl+Shift+T` сворачивают её до одной строки и разворачивают обратно. Состояние сворачивания не сохраняется между перезапусками.

Это только представление существующего `TODO.md`: без второго списка, записей в файл или вызовов модели. Панель замечает изменения файла, включая атомарную замену, примерно за секунду. Внешние правки и действия очереди используют один путь обновления. При повреждённом/недоступном файле показывается короткая ошибка вместо старых задач; исправление восстанавливает отображение.

Превью занимает не более шести строк и не более половины высоты терминала (минимум одна строка). Штатный режим развёрнутых tool outputs — по умолчанию `Ctrl+O` — показывает больше пунктов, но сохраняет лимит половины экрана. Изменение высоты/режима действует сразу, без чтения файла из render. Свёрнутая панель всегда остаётся одной строкой. Если терминал не различает `Ctrl+Shift+T`, используйте `/queue panel`; горячая клавиша обрабатывается штатным механизмом конфликтов Pi.

В headless/RPC и недоверенных проектах watcher не запускается. Reload/смена сессии/shutdown снимают старый watcher и виджет. Если при старте `TODO.md` ещё не было, после создания выполните `/queue panel`. Текст очищается от терминальных управляющих последовательностей и обрезается с `…` по ширине штатным TUI helper. Оформление вдохновлено rpiv-todo, но не вводит его session snapshots, новое хранилище или процент прогресса по всей Completed истории.

## Разделы TODO.md

Расширение распознаёт четыре служебных раздела:

```markdown
## In progress
## Pending
## Blocked
## Completed
```

Порядок разделов произвольный. Отсутствующие разделы считаются пустыми и автоматически добавляются при следующем изменении очереди. Одинаковый служебный раздел нельзя объявлять дважды.

Новые элементы получают скрытый ID:

```markdown
- [ ] Проверить preview <!-- pi-task:4a12bc90d881 -->
```

## Использование

```text
+ Проверить preview
/queue
/queue status
/queue panel
/queue edit <id> Новый текст
/queue delete <id>
/queue move <id> up|down|top|bottom
/queue next
/queue run
/queue pause
/queue resume
/queue skip
```

`/queue run` отказывается стартовать при занятом `In progress`. `/queue resume` явно продолжает текущую queue-задачу после перезапуска или паузы.

## Защита

- `TODO.md` — единственное хранилище задач.
- Запись под lock, через временный файл и атомарный `rename`.
- Конкурирующее изменение `TODO.md` прерывает операцию.
- Недоверенный проект не изменяется.
- `complete` требует совпадающий ID, summary и непустой список evidence.
- Автоматический commit/push отсутствует.

## Установка

Исходник: `todo-queue/`. Глобальная активная копия: `~/.pi/agent/extensions/todo-queue/`.

После копирования выполнить `/reload` или перезапустить pi.

## Откат

Удалить `~/.pi/agent/extensions/todo-queue/`, затем выполнить `/reload`.

## Проверки, привязанные к файлам (без Jev)

Для проверки кода запустите существующий process-only background runner через очередь:

```json
{"action":"check","id":"CURRENT_ID","command":"npm test","cwd":"pi-build","timeoutSeconds":600}
```

`cwd` относителен к рабочему каталогу сессии; по умолчанию используется он же. Проверка охватывает весь Git worktree выбранного проекта: tracked и неигнорируемые untracked файлы, включая удаления и executable bits. Вне Git сканируется выбранный каталог. Команда выполняется в указанном cwd, не в каталоге родительского TODO. Она остаётся обычной явно запрошенной локальной shell-командой, не sandbox и не автоматическое доказательство полноты тестов.

Вернутся check id и настоящий job id. Дождитесь штатного уведомления background runner. `action=checks` с текущим id при необходимости однократно считывает структурированный статус незавершённых jobs. Это не команда опрашивать статус циклом. Очередь не запускает моделей, Jev, таймеров проверки или автоматических повторов.

`complete` также однократно получает терминальные результаты и сравнивает снимки до запуска, при наблюдении завершения и перед закрытием задачи. Нужны status=completed и настоящий exitCode=0; слово PASS в логе ничего не доказывает. Новые/изменённые/удалённые файлы, изменённая задача, незавершённый job, недоступный runner или неизвестный снимок не позволяют закрыть задачу. После release/reclaim или нового dispatch старые проверки недействительны. Для каждого точного command/cwd нужна последняя успешная актуальная попытка; старую терминальную неудачу заменяет явный повтор той же команды. Все ещё работающие проверки должны закончиться. Записи находятся только в текущей ветке сессии, TODO остаётся единственным хранилищем статуса задач.

Задачи без записанных проверок сохраняют прежнее завершение по конкретному текстовому evidence (например, обсуждение или внешнее наблюдение). После первого `check` текст evidence уже не обходит его неудачу. Это добровольный механизм учёта, не защита от намеренного обхода через прямое редактирование TODO.

### Границы снимка

- Служебный TODO, его lock/temp и `.pi/tasks` исключены. Вне Git дополнительно исключены `.git`, `node_modules`, `.venv`, `__pycache__`, `.cache`, `coverage`, `test-results`. В Git tracked файлы сохраняются в scope независимо от ignore, кроме названных служебных файлов.
- Git-ignored untracked inputs, зависимости, переменные окружения и внешние сервисы не сертифицируются. Изменения такого входа требуют осознанного повтора проверки.
- Симлинки/submodules/специальные файлы отклоняются, а не молча пропускаются. Лимиты: 50000 файлов,256MiB,10s на снимок;100 check records на ветку сессии. Превышение/ошибка означает неизвестную актуальность, не PASS.
- Временную правку с восстановлением между наблюдениями механизм не обнаружит. Снимки не изолируют выполняемый тест и не предотвращают конкурентную запись после последнего сравнения. Снимок после проверки делается при явном наблюдении результата, не таймером в момент exit.
- Перезапуск/смена сессии не усыновляет старые процессы. Недоступный job остаётся unknown до явного повтора; эта возможность требует установленных bg_run/bg_status и актуального SDK с nested tool calls.
