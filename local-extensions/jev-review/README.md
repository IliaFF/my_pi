# Jev Review

Помощь DeepSeek и проверка Pi через встроенный `modelRegistry.classify`: OpenRouter `typesafe/jev-1.14`, при отсутствии в каталоге — `typesafe/jev-1.13`. Один владелец загрузки контекста и финального review, без перехвата provider stream.

## Использование

- `/jev-review status` — состояние и последний результат, вероятности, usage/cost.
- `/jev-review off` / `/jev-review on` — отключить/включить для текущей ветки сессии, включая явное включение для другой модели.
- `/jev-review auto` — включать автоматически только для ID семейства DeepSeek.
- `/jev-review check` — вручную проверить последний ответ, без запуска исправления. Работает также при выключенной автоматике.

Новые сессии: `auto`, помощь и classifier-вызовы включены только на DeepSeek. Смена ветки/сессии восстанавливает настройки из её собственных записей. Для работы ключ нужен в окружении процесса Pi либо в OpenRouter auth Pi; ключи и auth расширение не изменяет. После установки — `/reload` или новая сессия.

## Подгрузка и codemode

Перед работой Jev выбирает применимые скиллы из текущего SDK-каталога, без списка языков в коде. Явный `/skill:name` не отменяется оценкой. Файл скилла и доступные локальные Markdown-ссылки в его каталоге загружаются целиком: до 48 KiB на файл и до 96 KiB на всю секцию с заголовками. Небезопасные, внешние и не поместившиеся ссылки явно остаются незагруженными. Это не заменяет обязанность модели читать новые применимые инструкции. Неизвестный результат маршрутизации не означает, что скилл не нужен.

Из уже доверенного проектного контекста выбираются до трёх небольших релевантных фрагментов с путём и строкой. Нет внешнего поиска, исполнения ссылок или индексирования произвольной истории. Правила и состояние TODO/Firstmate не заменяются извлечёнными фрагментами.

Guidance предпочитает codemode для полезной оркестрации и обработки больших результатов: независимые вызовы можно объединять, зависимые решения разделяются, ошибки каждого результата проверяются. Одиночный прямой вызов или ответ без инструментов допустимы. Список инструментов и разрешения не изменяются. При смене модели устаревшая секция удаляется из отправляемого контекста.

## Поведение

На финальном `agent_before_settle` оцениваются четыре признака: проблема ответа, качества работы, завершения текущей задачи и соблюдения правил. При вероятности ≥0.8 по любой категории добавляется обратная связь и один дополнительный проход основного агента. Агент сначала подтверждает конкретную проблему; вероятность не разрешает опасные действия и не отменяет подтверждения пользователя.

Исправленный ответ проверяется ещё раз, но повторное исправление не запускается. Бюджет не сбрасывается на `agent_start`, tool turns, retries и compaction внутри одного prompt. Новый prompt сбрасывает бюджет. Чужие boundary drafts сохраняются. Aborted/error runs и границы с уже запланированным продолжением не проверяются.

Таймаут 8 секунд, retries=0. Общий бюджет — 64k символов сериализованного JSON. При превышении сокращаются контекст, TODO, выдержки evidence, запрос и ответ с `[OMITTED]`; правила сохраняются целиком. Если даже сокращённый payload не помещается, статус `unavailable`. Отсутствующая модель/ключ, ошибка сети и некорректные ответы также означают `unavailable`, не одобрение. `no-flags` означает лишь отсутствие сигнала по видимым данным. TODO никогда автоматически не закрывается и не переписывается.

## Что отправляется

Текущий запрос, ограниченные последние пользовательские сообщения, ответ, полный действующий system prompt (включая загруженные правила проекта), последние доступные чтения AGENT*/CLAUDE/CONTRIBUTING/SKILL.md, TODO до/после и до 20 последних результатов инструментов. Полные правила не обрезаются; при переполнении удаляются только точные дубликаты правил, уже содержащиеся в system prompt. Остальные большие тексты ограничены с маркером `[OMITTED]`, включая дополнительное сокращение для общего бюджета. Если правила и минимальные выдержки всё равно не помещаются, проверка пропускается с явным статусом. Сокращение может убрать существенные факты: `no-flags` не подтверждает корректность. TODO берётся из ближайшего родительского каталога; в недоверенном проекте автоматически не читается.

Аргументы инструментов не отправляются целиком. Для действий сохраняются краткая первая строка команды/путь и статус ошибки. Тела `read`/`write`/`edit`, обнаруженные diff outputs, изображения и thinking исключаются. Результаты shell/grep могут содержать небольшие фрагменты исходников. Markdown-правила могут содержать примеры кода. Diff не собирается автоматически.

Перед ограничением текста маскируются известные секретные переменные окружения, распространённые токены, Bearer, password/api_key/secret assignments и private keys. Это **best-effort, не DLP и не граница безопасности**: неизвестные секреты/форматы могут остаться. Для конфиденциальных проектов выключайте проверку до ввода запроса.

Проверка не исследует весь репозиторий и не доказывает качество кода без исходников/diff. Не гарантирует выполнение каждого правила, не заменяет тесты, подтверждения и права доступа.

## Записи и проверка

`jev-review` audit entries содержат только статусы, категории, вероятности, модель, usage/cost, размер payload (`payloadChars`), признак сокращения (`limited`) использование корректирующего прохода, длительность (`durationMs`) и безопасную категорию ошибки (`reason`); сырые provider errors и payload не сохраняется расширением. Стоимость вложенных classifier-вызовов не добавляется в стандартный footer/`/session` через boundary API; последняя стоимость доступна в `/jev-review status` и audit entry. Дополнительно к финальному review выполняется routing-вызов при наличии каталога скиллов; после исправления возможен ещё один review. Число вызовов и usage надо учитывать вместе. Категория правил различает `violated`, `complied`, `unknown`, `not_applicable`; неизвестность не является одобрением.

```bash
node local-extensions/jev-review/check.mjs
node local-extensions/jev-review/sdk-check.mjs
```

Проверки запускаются из корня исходников сборки. Они используют pinned SDK из `PI_CODING_AGENT_CORE_DIR` либо установленный Pi; SDK-проверка использует локальные фиктивные chat/classifier providers, временный HOME и запрет сети. Обе включены в `npm test`. Maintenance manifest восстанавливает `index.ts`, `workflow.ts` и `privacy.ts`; installer backup включает каталог расширения.

Локальная диагностика: `$PI_CODING_AGENT_DIR/jev-review/workflow.jsonl` (по умолчанию `~/.pi/agent/jev-review/workflow.jsonl`), каталог 0700, файлы 0600. Записи содержат активацию, вероятности выбора, пути/хеши источников, пропуски, связанные direct/nested tool events без аргументов, review, duration и usage. Лимит файла 2 MiB, одна предыдущая копия `.1`, rotation и чрезмерные записи помечаются. Полные файлы, запросы, ответы, скрипты codemode и reasoning в этот журнал не записываются. Имена источников и session/branch identifiers остаются приватными метаданными; не публикуйте журнал без проверки. Это ограничение локальных логов не отменяет описанную выше передачу контекста внешнему classifier.
