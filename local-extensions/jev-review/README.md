# Jev Review

Глобальная проверка Pi через встроенный `modelRegistry.classify`, OpenRouter `typesafe/jev-1.13`. Без SDK-зависимостей и без перехвата provider stream.

## Использование

- `/jev-review status` — состояние и последний результат, вероятности, usage/cost.
- `/jev-review off` / `/jev-review on` — отключить/включить для текущей ветки сессии.
- `/jev-review check` — вручную проверить последний ответ, без запуска исправления. Работает также при выключенной автоматике.

Новые сессии: включено. Смена ветки/сессии восстанавливает настройки из её собственных записей. Для работы ключ нужен в окружении процесса Pi либо в OpenRouter auth Pi; ключи и auth расширение не изменяет. После установки — `/reload` или новая сессия.

## Поведение

На финальном `agent_before_settle` оцениваются четыре признака: проблема ответа, качества работы, завершения текущей задачи и соблюдения правил. При вероятности ≥0.8 по любой категории добавляется обратная связь и один дополнительный проход основного агента. Агент сначала подтверждает конкретную проблему; вероятность не разрешает опасные действия и не отменяет подтверждения пользователя.

Исправленный ответ проверяется ещё раз, но повторное исправление не запускается. Бюджет не сбрасывается на `agent_start`, tool turns, retries и compaction внутри одного prompt. Новый prompt сбрасывает бюджет. Чужие boundary drafts сохраняются. Aborted/error runs и границы с уже запланированным продолжением не проверяются.

Таймаут 8 секунд, retries=0. Общий бюджет — 64k символов сериализованного JSON. При превышении сокращаются контекст, TODO, выдержки evidence, запрос и ответ с `[OMITTED]`; правила сохраняются целиком. Если даже сокращённый payload не помещается, статус `unavailable`. Отсутствующая модель/ключ, ошибка сети и некорректные ответы также означают `unavailable`, не одобрение. `no-flags` означает лишь отсутствие сигнала по видимым данным. TODO никогда автоматически не закрывается и не переписывается.

## Что отправляется

Текущий запрос, ограниченные последние пользовательские сообщения, ответ, полный действующий system prompt (включая загруженные правила проекта), последние доступные чтения AGENT*/CLAUDE/CONTRIBUTING/SKILL.md, TODO до/после и до 20 последних результатов инструментов. Полные правила не обрезаются; при переполнении удаляются только точные дубликаты правил, уже содержащиеся в system prompt. Остальные большие тексты ограничены с маркером `[OMITTED]`, включая дополнительное сокращение для общего бюджета. Если правила и минимальные выдержки всё равно не помещаются, проверка пропускается с явным статусом. Сокращение может убрать существенные факты: `no-flags` не подтверждает корректность. TODO берётся из ближайшего родительского каталога; в недоверенном проекте автоматически не читается.

Аргументы инструментов не отправляются целиком. Для действий сохраняются краткая первая строка команды/путь и статус ошибки. Тела `read`/`write`/`edit`, обнаруженные diff outputs, изображения и thinking исключаются. Результаты shell/grep могут содержать небольшие фрагменты исходников. Markdown-правила могут содержать примеры кода. Diff не собирается автоматически.

Перед ограничением текста маскируются известные секретные переменные окружения, распространённые токены, Bearer, password/api_key/secret assignments и private keys. Это **best-effort, не DLP и не граница безопасности**: неизвестные секреты/форматы могут остаться. Для конфиденциальных проектов выключайте проверку до ввода запроса.

Проверка не исследует весь репозиторий и не доказывает качество кода без исходников/diff. Не гарантирует выполнение каждого правила, не заменяет тесты, подтверждения и права доступа.

## Записи и проверка

`jev-review` audit entries содержат только статусы, категории, вероятности, модель, usage/cost, размер payload (`payloadChars`), признак сокращения (`limited`) использование корректирующего прохода, длительность (`durationMs`) и безопасную категорию ошибки (`reason`); сырые provider errors и payload не сохраняется расширением. Стоимость вложенных classifier-вызовов не добавляется в стандартный footer/`/session` через boundary API; последняя стоимость доступна в `/jev-review status` и audit entry. Обычно один Jev-вызов на prompt, два при исправлении.

```bash
node ~/.pi/agent/maintenance/local-extensions/jev-review/check.mjs
```

Assert-проверка без фреймворков использует `jiti` установленного Pi. Исходник: `index.ts`; активная копия: `~/.pi/agent/extensions/jev-review/index.ts`. Maintenance manifest восстанавливает только runtime-файл из этой сохранённой копии.
