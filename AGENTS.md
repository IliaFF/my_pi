# Сборка Pi: обязательный порядок

Источник истины — этот репозиторий. `~/.pi/agent/maintenance` — установленная копия, не место для первичных правок. Личный runtime не копировать в Git. При работе из fresh_pi учитывать родительский TODO.md; не выбирать автоматически посторонние задачи.

1. До правок прочитать затронутые `openspec/specs/*/spec.md` и создать change через `/opsx-propose` либо `openspec new change <name>`.
2. Указать причину, затронутые capabilities, design при рисках, задачи и проверяемые сценарии. Для багов сначала failing regression; для tooling без изменения поведения допускается `skip_specs: true`.
3. Код, callers, конфиги, snapshots и тесты менять согласованно. Новые особенности не добавлять заодно. Production/credentials не менять автоматически.
4. `npm test` — обязательный gate. Нельзя заменить SDK integration статическими строковыми проверками или mock callback. Проверить также полный diff.
5. Результаты, версии, причину отказа и ограничения записать в change. Архивировать только после PASS и завершённых tasks; CI запуск отдельно отметить как непроверенный, если нет реального job.
6. Делать commit исходников вместе с specs/tests. Production установка/обновление — отдельное согласованное действие с backup; для rollback читать `docs/diagnostics-and-rollback.md`.

Платные/внешние live проверки — отдельно, только с согласованием. Не коммитить test-results, npm dependencies, пользовательские логи или дампы сессий. Проверки без credentials не доказывают работоспособность Telegram, Chrome, SSH и провайдеров.
