# Ежедневный обзор расширений

Отдельный read-only monitor для VPS, согласованный пользователем: текущая ChatGPT/Codex-подписка, не более одной модельной партии и 10 кандидатов за UTC-сутки, результаты через существующий Hermes Telegram. Он **не устанавливает расширения и не меняет сборку**, не заменяет updater.

## Источник и пределы

Запросы к registry идут не чаще одного в 2,5 секунды. Ответ `429` допускает максимум два повтора с числовым Retry-After до 120s (без заголовка — 60s); больший/неподдерживаемый интервал означает отказ до следующего запуска. Это не гарантия отсутствия rate limit на общем IP.

Источник — официальный npm search API, точное слово `pi-package` (критерий попадания пакета в Pi gallery). HTML pi.dev при исследовании отвечал HTTP403. Это не обещание идентичности редакторскому каталогу pi.dev: Git-only пакеты, удалённые/скрытые записи и запаздывание индекса могут отличаться. Пагинация ограничена первыми 10 000 ранжированных поисковых записей (40 страниц): при глубоком offset npm молча возвращает начало вместо продолжения. Если total больше окна, coverage.truncated=true. Total выше 25 000 считается неожиданным изменением источника и требует пересмотра лимита. Дополнительно: 300s плюс текущий запрос/его ограниченные повторы (25s socket timeout), 4MiB на ответ; неполная страница, сетевой отказ или превышение лимита отклоняют скан без замены прежнего snapshot. Дубли удаляются; число полученных/уникальных записей, дублей и начальный/конечный total сохраняются в coverage. Покрытие всегда помечено exhaustive=false: обход всех поисковых страниц не равен полному каталогу. Для всех страниц одного обхода используется общий уникальный cache namespace, чтобы не смешивать старые CDN-страницы. Но даже свежий ranked search не предоставляет стабильный snapshot: живые VPS-проверки подтвердили пересечения страниц. Монитор честно анализирует обнаруженную выборку, а не гарантирует исчерпывающий обход всех расширений.

Первый скан фиксирует baseline и оставляет максимум 10 seed-кандидатов, а не очередь из тысяч старых пакетов. Далее — новые версии/пакеты, с сохранением pending между запусками. Уже установленные прямые зависимости исключены: ими занимается updater. Приоритет — совпадения с focus профиля, затем более свежие записи. Успешно записанные обзоры одинаковой версии не повторяются. Отказ модели расходует попытку дня; повтор возможен на следующий день. Это ограничение партий, **не гарантия фиксированного расхода токенов**: внутренние повторы провайдера и стоимость зависят от подписки.

Tarball разрешён только с registry.npmjs.org и проверяется по SHA512. Максимум 4MiB compressed, 16MiB объявленного expanded размера, 1000 members. Нет extraction, symlinks, traversals или исполнения npm/lifecycle/code. До пяти текстовых фрагментов/12KB на пакет, до десяти пакетов; такой обзор неполон по определению. Пакет с отвергнутым архивом/целостностью пропускается до новой версии; список — `state.json/rejected`. Сетевой сбой не считается непригодностью версии.

## Установка и проверка

Исходник — Git pi-build; на VPS должен уже существовать одобренный updater/runtime, direct-access OAuth и рабочий Hermes. Из checkout с проверенным commit:

```sh
sudo bash deployment/extension-research/install.sh
sudo python3 /opt/my-pi-extension-watch/vps-extension-watch.py --check
# После отдельной проверки sandbox/модели/доставки:
sudo systemctl start my-pi-extension-watch.service
sudo systemctl enable --now my-pi-extension-watch.timer
systemctl list-timers my-pi-extension-watch.timer
```

Installer не включает timer и не вызывает npm/модель. При повторной установке сохраняет прежние owned-файлы в `/var/backups/my-pi-extension-watch/<timestamp>-<pid>`, не меняет состояние уже существующего timer. Активный запуск должен завершиться либо быть остановлен оператором. `--check` сканирует/сохраняет baseline и кандидатов, **не читает OAuth и не вызывает модель/Telegram**. Уже выданная попытка в `state.json` не сбрасывается reinstall.

Модель: закреплённый CLI существующего updater, чистый HOME, env без API keys, OAuth только OpenAI. Общий updater run.lock сериализует использование/refresh подписки; при занятом updater обзор пропускается до следующего запуска. Worker — отдельный UID `pi-extension-review`, systemd sandbox без /root, shared auth, tools, MCP, extensions, AGENTS, skills и sessions; 900s, 1GiB, 64 tasks, read-only host. При refresh root сохраняет только проверенные OAuth поля; неправильный документ не перезаписывает прежний grant. **Это намеренное совместное использование подписки, не новая авторизация**.

Расписание: ежедневно 06:00 UTC плюс до 20 минут случайной задержки; Persistent=true может запустить пропущенную проверку при включении. Контроллер: максимум 1800s/512MiB. Telegram outbox сохраняется до успешного send; повторный запуск пытается доставить накопленное без повторного обзора. Возможен дубль после crash между send и сохранением подтверждения. После 30 недоставленных частей новые модельные партии приостанавливаются. Повтор доставки — при следующем ручном/ежедневном запуске.

## Диагностика и откат

`/var/lib/my-pi-extension-watch/`: state.json, latest-check.json, latest-review.json (public inputs + валидированный результат + revision профиля), latest-error.json (только статус/дата, без OAuth exception bodies). Нет бесконечного архива отчётов: предыдущие latest перезаписываются, jobs с credentials удаляются по завершении. Не публиковать state/logs без отдельной проверки.

Профиль — portable `deployment/extension-research/stack-profile.json`, зависимости и Git revision добавляются при установке. Он не читает личный runtime и может устареть: переустановить после изменения стека. Ответ модели недоверенный, это рекомендации для человека, не команды к исполнению.

Остановка: `systemctl disable --now my-pi-extension-watch.timer; systemctl stop my-pi-extension-watch.service`. Worker связан через PartOf. При аварийном SIGKILL/power loss перед следующим запуском удалить **только** остаточные `/var/lib/my-pi-extension-jobs/review-*` после проверки отсутствия worker. Для удаления сервиса убрать только его два unit-файла, /opt/my-pi-extension-watch и /etc/my-pi-extension-watch, затем daemon-reload; state/backups можно сохранить. UID оставлен без login. Не трогать updater/runtime/auth/Hermes. Восстановление предыдущего monitor — только из его конкретного backup; общие OAuth-файлы назад не откатывать.

Offline gate не доказывает живую доступность npm, подписки, Telegram, качество рекомендаций или совместимость пакета. Реальные deployment/sandbox/model/delivery evidence записываются отдельно в OpenSpec change.
