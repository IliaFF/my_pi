# Удалённые хосты

Правила локальны для этого ПК: в Git-репозитории и общие конфиги сборки они не переносятся.

**Алиас — единственный адрес.** Имя хоста, порт, пользователь и путь к ключу живут в `~/.ssh/config`.
Ни здесь, ни в проектных файлах они не дублируются; приватные ключи, пароли и токены не читаются и не
выводятся.

Назначение и ресурсы машин — со слов пользователя. Фактическая доступность проверяется перед работой,
а не берётся из памяти.

## Машины

| Алиас | Что даёт | Ограничение |
|---|---|---|
| `office` | CPU и NVIDIA GTX 1050, 3 ГБ видеопамяти | — |
| `iii` | много CPU | доступ к GPU нестабилен: без проверки на него не рассчитывать |
| `ubercomp` | CPU, контейнер | это не хост: файловая система, права и зависимости другие |
| `ubercomp-host` | CPU, хост под `ubercomp` | своё окружение, контейнером не подменяется |
| `ubercomp-hw3run-host` | тот же хост под `hw3run` | свой пользователь и свои права |
| `agentVPS` | постоянно работающая машина автоматизации и координации, SSH jump-хост для остальных | ресурсы и память ограничены, тяжёлые вычисления по умолчанию не сюда |

Порядок выбора: `office`, затем `iii`, затем уберкомп. Перед GPU-задачей наличие подходящего GPU
проверяется, а не предполагается.

## Подключение

1. `remote(action="status")` — готово, когда видно, подключено ли и куда направлен routing.
2. `remote(action="connect", command="ssh <алиас>")` — готово, когда статус показывает нужный endpoint.
3. `remote(action="chdir", cwd="...")`, если нужен другой каталог; готово, когда каталог назван.
4. `remote(action="exec", remoteCommand="...", timeout=N)` — вывод ограничивается `tail`, `sed` или
   `rg` с лимитом. Требования к timeout проверяются в описании самого инструмента `remote`.
5. `remote(action="disconnect")` перед локальными правками: при активном SSH routing `read`, `write`,
   `edit` и `bash` работают удалённо, поэтому routing проверяется до изменения локального файла.

Серверные заметки лежат в памяти сервера и не заменяют общие правила подключения: точный путь берётся
через `remote(action="memory")`, правка — через `read`/`edit` по этому пути.

## Маршрут и ловушки

- `remote(action="reconnect")` восстанавливает последнюю сохранённую команду, а не обязательно нужный
  хост. В сохранённом маршруте может стоять явный IP и другой путь к ключу: назначение проверяется, а
  команда заменяется на алиас.
- `ubercomp-host` ходит через `moscow`, остальные профили — через `agentVPS`. Старые `-J` и `-p` из
  истории не возвращаются.
- Прямой `ssh` через shell не используется: маршрут, ключи и `ProxyJump` держит `remote` с
  Host-алиасами из `~/.ssh/config`.
- Windows читает `C:\Users\ilyaz\.ssh\config`, WSL — `~/.ssh/config`; блоки `moscow` и `ubercomp-host`
  держатся согласованными. В WSL `IdentityFile` указывает на существующий Windows-ключ
  `/mnt/c/Users/ilyaz/.ssh/ubercomp_host_ed25519`, копия ключа не создаётся.
- `agentVPS` держит `ForwardAgent yes`, то есть удалённый хост видит SSH-агент. Состояние берётся из
  конфига, а не из памяти; forwarding без необходимости не включается.

## Границы

SSH-конфигурация, установка ПО, перезапуск служб и туннели меняются только по явному разрешению
пользователя. Проверка ключей хостов не ослабляется.
