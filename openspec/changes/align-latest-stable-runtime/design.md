# Design

Reuse install.sh backup/rollback and full gate; add explicit --preserve-settings rather than a second deploy framework. Existing settings.json keeps all fields except matching explicit npm pins, aligned to exact runtime lock; unpinned/custom/local references retain shape. Preserve APPEND_SYSTEM.md and existing my-pi-settings.json byte-for-byte. Missing personal files bootstrap portable defaults. Native MCP merge retains custom entries. Managed extensions remain governed by source; obsolete paths removed under backup. Auth, models, sessions, remote memory and context stores outside managed set remain untouched (existing context.db permissions may harden).

Run isolated preservation regression before edit (RED). Refresh source locks, npm ci, patch apply, release replay, npm test. Commit/push main and await CI before approved deployment. Record pre-install private digests, compare post-install sensitive stores and settings minus changed pins, full host gate. Installer automatic rollback on failure; independently verify restored state before claiming rollback success. Backup includes previous maintenance and npm; never Git commit runtime or backups. Current process cannot hot-reload safely: user restarts Pi after completion.
