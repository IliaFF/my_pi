# Design

Allow the standard Pi tools read, bash, edit, write, grep, find and ls, as additionally approved by the operator. Keep all other launch settings and add no dependency. Replace contradictory blanket bans rather than append an exception.

Production code means code shipped with or used by the working product, regardless of branch or deployment state. Explicitly assigned tests, fixtures, disposable scripts and documentation are allowed only when they are not part of production. Names or file types alone do not establish that boundary. Ambiguity stops execution and returns to the parent.

The parent specifies allowed paths, purpose, constraints and completion checks, owns planning and acceptance, and reviews the full diff. One writer per cwd/worktree. Global delegation thresholds and resource approval remain unchanged.

# Verification and limits

Use existing real SDK with a synthetic provider to inspect the actual child prompt; assert the permission, prohibition, ambiguity rule and absence of the old blanket bans. This checks instruction delivery, not model obedience or OS enforcement. Full npm test and diff review are required. The same assistant can edit tests and instructions; no independent control or new enforcement infrastructure is claimed. Runtime stays unchanged.
