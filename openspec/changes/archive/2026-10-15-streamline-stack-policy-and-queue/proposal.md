## Why

An explicit task_queue claim id is ignored and the wrong pending task is claimed, causing release/move/claim churn. Failed tool operations are returned as successful results. Overlapping and project-specific policy encourages oversized orchestration. The user requested a whole-installed-stack offline audit, background tests and a reusable global APPEND, with approved activation after checks.

## What Changes

Honor an explicit pending task id without reordering; retain FIFO when omitted and deterministic legacy id injection. Surface failures through native tool errors. Consolidate portable APPEND with personal communication/critical-feedback requirements, bounded orchestration, conditional task tracking and safe recovery. Add real SDK queue coverage and policy regression assertions; run source/host and whole configured offline startup. Record per-component coverage, deferred improvements and unverified external features. No package removal or exposure switch without evidence.

## Capabilities

### New Capabilities
- `task-selection`: explicit id selection, FIFO default, atomic rejection and truthful errors.
- `general-agent-policy`: portable, task-conditional communication/tool/recovery rules.

### Modified Capabilities
- `build-validation`: real SDK queue coverage and prompt-policy checks.

## Impact

Queue core/tool/schema/docs and their tests; portable APPEND; test gate and reinstall snapshots. Runtime activation/APPEND copy with backups is approved for this task. No paid calls, MCP transports, agents in background, arbitrary cache tuning or baseline/profiler pilot changes.
