# Design
Keep existing automatic-compaction lifecycle and native reserve protection. Change the extension's effective cap from 170000 to 500000, not model metadata; the native check remains authoritative near a smaller model window. Preserve keepRecentTokens=12000 and reserveTokens=12500. Extension triggers at >=500000, native trigger remains >contextWindow-reserveTokens. No global per-model reserve overrides are needed.

Install the exact upstream Canary package, with a version-gated patch rather than a competing implementation. Distributed fixed markers cover beginning/middle/end; distribution can invalidate cache even with fixed tokens. Three failures trigger ctx.compact(), whose lifecycle reason is manual. The local extension must not start another continuation for that reason. Canary owns its onComplete/onError continuation and marks phase responding so the hidden check does not restart before the original request is answered. Remove upstream instructions to return vanished markers after compacting.

Keep context-fold as sole summary owner. Test stock failure before applying patch, then real SDK successful and failed compaction, normal verification, and preserved original prompt. No provider credentials in tests. Production deployment backs up exactly the affected settings, extension and npm metadata/package; preserve other packages/settings and all existing patches. Existing Pi process needs reload/restart; file installation is not evidence of active hot reload.

The first full gate exposed a test-isolation bug: SessionManager.inMemory has an empty session directory, and context-fold consequently writes relative to process cwd, even when the SDK cwd is a temporary fixture. Use SessionManager.create with an explicit temporary session directory and assert that directory before binding extensions. Preserve already leaked synthetic artifacts outside the repository; do not exempt them from the release scan.
