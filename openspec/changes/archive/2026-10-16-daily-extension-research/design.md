# Design

Use Python stdlib and the installed pinned VPS Pi CLI. Fetch the public npm search corpus with exact pi-package keyword filtering (official Pi package gallery eligibility), bounded pagination/body/time limits; direct pi.dev HTML returned HTTP403, so do not make the scheduler depend on a browser or claim identical gallery coverage. Commit a search snapshot only after all required pages succeed. Live VPS probes confirmed npm ranked pagination overlaps even with fresh uncached pages; deduplicate by package name, record coverage counts/duplicates/total drift, and always label coverage non-exhaustive. Deep npm offsets silently restart at page zero in live probes; stop at the first 10,000 ranked records and disclose truncation when total exceeds that window, rather than promise full enumeration. A stopped page walk is failure and starts no model work. Use one cache namespace per walk and 2.5s request pacing with at most two bounded numeric Retry-After retries. Keep changed/versioned candidates pending until their single daily batch is attempted; mark failed attempt/day before invoking the model so restart never spends a second model run that day. Persist reviewed versions and an outbox, bound disk retention, never execute package code or installation scripts.

Rank candidates deterministically against a portable explicit stack profile, prefer new/changed useful non-installed packages and avoid re-reviewing identical versions. First run is a baseline plus at most ten relevant seed candidates, not thousands of model jobs. Fetch tarballs from registry.npmjs.org only, enforce transport/expanded-byte/member/path bounds and integrity; read selected text members without extraction or execution. Excerpts are partial, carry path/hash/truncation markers, and cannot confer authority. The model sees only public candidate excerpts + curated stack metadata, with no tools/MCP/extensions/context files, no private sessions or SSH/Hermes credentials.

Separate root-owned controller/state, non-root worker UID, temporary worker HOME containing only approved OpenAI OAuth and fixed in-memory work. Hold the existing updater run.lock plus own lock while using/refreshing the shared subscription; if updater is busy, skip rather than race. Persist only validated direct-access OAuth fields, retaining clientId/scopes; invalid worker output never overwrites the old grant. Preserve updater code/timer/config and all root/PC credentials. Worker systemd sandbox enforces timeout, memory/disk/process limits, hides /root/home/updater auth and state, and denies system writes. No need for a general autonomous agent or untrusted tools.

One model batch/day, maximum ten packages, 900s; deterministic discovery/check sends no model requests. Telegram receives only bounded validated consider entries with concrete potential stack benefit and canonical references, never skip/already-covered reviews, empty digests, raw model logs or OAuth. The full batch remains local. This was explicitly required by the user after the first live test. Archive member names are bounded to 1024 UTF-8 bytes without controls, and serialized model input to 400KB including JSON escape expansion. Delivery is at-least-once via durable outbox (a crash after send may duplicate a message), not falsely exactly-once. Timer daily06:00UTC with small random delay, disabled until live checks/explicit approved activation. Manual check does not enable model calls. Installation saves relevant pre-state; new service is reversible by stop/disable and removal of owned files, never restore someone else's credentials.
