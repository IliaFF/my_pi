# Design

Use explicit task_queue action=check with id, command, optional cwd and timeoutSeconds. It wraps the existing bg_run via native ctx.executeTool, with isAgent=false, triggerOnCompletion=false and notifications enabled. No separate runner or event service. checks and complete deliberately inspect pending jobs once through bg_status; a running result is not a request to poll. A check is terminal only from structured package task metadata, never printed logs.

Snapshot the selected project (cwd defaults to session cwd), not the ancestor containing TODO. In Git use the worktree root and all tracked plus nonignored untracked files, including deletion markers for tracked deleted files and executable bits. Outside Git walk the selected directory, excluding dependency/cache/output directories. Exclude the authoritative TODO, its lock/temp files and background runtime outputs under .pi/tasks. Track ignored inputs as outside this snapshot's proof scope; ignored config, dependencies, external services and environment are not certified. Reject symlinks/submodules/unsupported files rather than silently certify external inputs. Bound files/bytes/time; failure is unknown, never PASS. Compare pre-run, terminal-observation and completion snapshots. No guarantee against temporary edits restored between observations or writes after the final comparison.

Persist records using pi.appendEntry and restore only current branch entries. No second task store; TODO remains authoritative. Record task text as well as stable id, so editing the objective invalidates its evidence. Release/reclaim or dispatching a new lifecycle invalidates previous records for that id; do not silently remove required checks. On session replacement pending work is not adopted: records fail closed until an explicit rerun if the background service cannot resolve them.

Checks are opt-in to preserve discussion, documentation and direct-observation tasks. After opting in, free-text evidence cannot override a failed/stale/unknown record. All pending records must settle, then the latest record per exact command/cwd must pass. This is freshness bookkeeping, not proof that the chosen command adequately tests the requirement or is read-only. Commands remain explicitly requested unsandboxed local shell.

Completion validation runs inside the existing TODO lock; extend mutateTodo to await callbacks while retaining concurrent TODO byte checks; a stale-mtime lock owned by a live process cannot be stolen during async validation. Session-bound records are never transferable across sessions/branches. Tests use temporary projects and actual SDK/bg package with no credentials/providers, bounded child lifetimes. No production deployment.
