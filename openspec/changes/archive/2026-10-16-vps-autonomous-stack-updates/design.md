# Design
## Trusted boundary
Installed controller outside checkout is root-owned. Only it has GitHub SSH and Hermes access. Repair uses its own UID, a copy of Codex OAuth only, no personal extensions, strict systemd filesystem hardening, deadlines, 2 GiB job tmpfs and resource limits. Canonical OAuth stays root-only; only an ephemeral agent HOME receives it, and validated refresh results are persisted even after repair failure. Tests use another UID and temporary HOME without OAuth. The controller NEVER invokes Git from an agent-controlled .git or executes checkout scripts as root. Candidate files are copied as bounded regular files into a private trusted checkout; symlinks and protected edits fail closed.

## Acceptance
Daily npm latest detection only accepts stable exact semver newer than current pins; core and TUI stay aligned. Package names, package scripts, native-script policy, managed configs, tests, CI, controller and instructions cannot be modified by repair. Allow dependency pins/lock, versioned patches, local extensions, Markdown docs and one new archived OpenSpec change. Manifest metadata can change only where required for patch migration; managed settings remain protected.
The original mandatory gate runs from a fresh credential-free copy. Compare accepted input bytes before/after tests. The controller, not the model, commits that snapshot and pushes an automation branch. Public GitHub API verifies the trusted test.yml push workflow for that exact SHA/branch. Main must still equal the recorded base; fast-forward publication only. A direct-parent check plus an explicit --force-with-lease=refs/heads/main:<base> compare-and-swap rejects concurrent changes (including rewinds); the lease never authorizes history rewriting. No unchecked force push, skipped checks or branch-protection bypass.

## Persistence and limits
flock prevents overlap. Atomic state stores attempt counts, pending candidate and notification outbox. Resume pending CI before starting another agent. At most three repair attempts per base/target fingerprint; 45-minute repair and 15-minute gate, bounded disk/logs; job directories removed after processes stop. Save private evidence outside public Git. CI timeout or API outage never permits merge. New base/release permits retry.
No separate GitHub token is needed for this public repo; unauthenticated API rate limits fail closed. GitHub branch protection rejecting a direct checked fast-forward is a blocker, never bypassed.

## OAuth
The initial user-authorized legacy credential-copy experiment failed: native Pi 1.3 sends OpenAI direct requests, while the legacy Codex grant lacks api.responses.write. A diagnostic CLI downgrade also hit an incompatible transitive SDK. Neither is accepted as working. The user subsequently authorized preparing a separate login.
Use pinned Pi/AI/TUI 1.3.0 and the public OpenAI provider OAuth login, with a dedicated persistent device ID. The helper receives the browser callback on VPS loopback 1455 through an SSH forward and has a 14-minute deadline. It prints authorization URL/status only, validates subscription scope, and atomically saves root-private auth. Preserve clientId/scopes through every refresh. Login failure never overwrites an existing credential. No root/PC auth writes, API credentials, fallback or public callback listener. An offline self-check covers invalid credentials and atomic save; live login/response remain required before enabling the timer.

## Scope and limitations
Automatic repair cannot edit its judge. Upstream changes requiring test/CI/controller/managed-config modifications are held for manual review. Model-authenticated operation is not a proof of future repair quality. Timer watches releases daily, not instantaneously; no production deployment occurs.
