# Spec Delta

## MODIFIED Requirements

### Requirement: Восстановление проверяет целостность
Процедура восстановления MUST проверять целостность backup и допустимые назначения до записи, сохранять исходники отдельно от runtime и не объявлять успешным непроверенный откат. Installer rollback MUST принимать внутренние относительные ссылки и отвергать выход за управляемые пути до удаления текущих файлов. Manual и automatic installer rollback MUST применять одинаковые проверки.

#### Scenario: Повреждённый backup
- **WHEN** payload backup изменён после создания
- **THEN** восстановление отклонено и текущий управляемый файл не изменён

#### Scenario: Восстановление управляемого файла
- **WHEN** управляемый файл изменён после backup
- **THEN** проверенный backup восстанавливает исходное содержимое

#### Scenario: Installer backup содержит обычную npm-ссылку
- **WHEN** installer backup содержит `.bin/jiti -> ../jiti/lib/jiti-cli.mjs` внутри управляемого npm-дерева
- **THEN** rollback восстанавливает файл и относительную ссылку с исходным target без выхода за управляемые назначения

#### Scenario: Backup пытается обратиться к неуправляемым данным
- **WHEN** archive member, symlink, hardlink или цепочка ссылок выходит за agent либо разрешённые управляемые пути
- **THEN** rollback завершается ненулевым кодом до удаления или изменения текущих managed и unmanaged файлов

#### Scenario: Проверка или распаковка backup не завершена
- **WHEN** backup отсутствует, повреждён, содержит специальный файл или не может быть полностью подготовлен
- **THEN** текущие managed файлы остаются неизменными и успешное восстановление не объявляется

#### Scenario: Automatic rollback после ошибки installer
- **WHEN** installer получает ошибку после изменения managed файлов
- **THEN** он использует тот же проверяемый rollback, что manual uninstall; отказ восстановления явно сообщается и не маскируется как PASS
