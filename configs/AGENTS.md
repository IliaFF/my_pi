# Локальные правила этого ПК

## Удалённые хосты и вычислительные ресурсы

Правила локальны для этого ПК; не копировать их в Git-репозитории или общие конфиги сборки. Адреса, порты, пользователей и пути к ключам брать из актуального `~/.ssh/config`, не дублировать в проектных файлах, приватные ключи, пароли и токены не читать и не выводить.

Назначение и ресурсы со слов пользователя; фактическую доступность проверять перед работой.

- `office`: CPU и NVIDIA GTX 1050 с 3 ГБ видеопамяти.
- `iii`: много CPU; доступ к GPU нестабилен, не рассчитывать на него без проверки.
- Уберкомп: CPU. Различать хост и контейнер: `ubercomp` — контейнер, `ubercomp-host` — хост под `ubercomp`, `ubercomp-hw3run-host` — тот же хост под `hw3run`; не подменять окружения и не считать их файловые системы, права и зависимости одинаковыми.
- `agentVPS`: постоянно работающий сервер для автоматизации и координации, также SSH jump-хост для остальных машин; ресурсы и память ограничены, тяжёлые вычисления по умолчанию на него не выбирать.

Выбирать машину в порядке `office` > `iii` > уберкомп с учётом требований задачи, доступности и текущей загрузки; перед GPU-задачей проверять наличие подходящего GPU.

## Подключение через Pi

- Для SSH использовать tool `remote` с Host-алиасами из `~/.ssh/config` и `ProxyJump`, не обходить его прямым SSH через shell.
- Перед удалённой работой проверять `remote(action="status")`, окружение выбирать через `remote(action="connect", command="ssh <Host-алиас>")`, рабочий каталог менять через `remote(action="chdir", cwd="...")`; для `remote exec` задавать конечный timeout и ограничивать вывод; для серверных заметок сначала брать точный путь через `remote(action="memory")` и не путать память сервера с общими правилами подключения.
- Хост уберкомпа доступен как `remote(action="connect", command="ssh ubercomp-host")`: SSH-конфиг направляет его через `moscow`, не через `agentVPS`. Не подменять алиас контейнером `ubercomp` или пользователем `hw3run` и не возвращать старые `-J`/`-p` из истории.
- Windows использует `C:\Users\ilyaz\.ssh\config`, WSL — `~/.ssh/config`; блоки `moscow` и `ubercomp-host` держать согласованными. В WSL `IdentityFile` хоста ссылается на существующий Windows-ключ `/mnt/c/Users/ilyaz/.ssh/ubercomp_host_ed25519`, без копирования ключа.
- При проверке 2026-07-17 у `agentVPS` был включён `ForwardAgent yes`; актуальное состояние брать из SSH-конфига. Учитывать риск доступа удалённого хоста к SSH-агенту; forwarding без необходимости дополнительно не включать.
- `remote(action="reconnect")` восстанавливает последнюю сохранённую команду, а не обязательно нужный хост; сохранённый маршрут может содержать явный IP и другой путь к ключу, поэтому сначала проверить назначение и заменить команду на Host-алиас.
- При активном SSH routing `read`, `write`, `edit`, `bash` работают удалённо; перед изменением локальных файлов убедиться, что routing локальный, и вернуть его через `remote(action="disconnect")`.
- Не менять SSH-конфигурацию, не устанавливать ПО, не перезапускать службы и не менять туннели без явного разрешения пользователя. Не ослаблять проверку ключей хостов.
